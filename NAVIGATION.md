# Cain — Codebase Navigation Guide

This file is a map of the **Improving-Assessment** branch. Use it to find the right place to work before changing code.

> **Important:** This guide describes what the files currently do. Some parts are unfinished or appear to be leftovers from earlier versions. A file being listed here does not mean its feature is currently connected or working.

## 1. Project at a glance

Cain currently has two main parts:

- **Backend (`backend/`)** — Python and FastAPI. It retrieves GitHub data, calculates repository-quality scores, and returns data to the frontend.
- **Frontend (`frontend/Cain/`)** — React and Vite. It accepts a GitHub username, calls the backend, and displays profile, activity, and repository-quality information.

## 3. Backend map

### Entry point

- **`backend/main.py`** — Creates the FastAPI application, configures CORS, registers the leaderboard router, and defines the `POST /` endpoint. That endpoint coordinates GitHub data collection, repository scoring, activity analysis, and the final JSON response.

### GitHub data collection

- **`backend/services/dataCompile.py`** — Contains `FetchData`. It makes requests to GitHub's API and formats the user's profile, events, repository list, and root-level repository contents. If you need Cain to collect another piece of GitHub data, this is the current starting point.

### Analysis

- **`backend/services/repo_analyser.py`** — Contains `RepoAnalyser`. It currently has repository metadata helpers (such as age, last-push age, activity level, and fork status) and a repository-content check for files/folders such as README, tests, LICENSE, `.gitignore`, and Dockerfile. The content check currently examines the repository's root contents, not the full nested file tree.
- **`backend/services/analyser.py`** — Contains `GitHubAnalyzer`. It summarizes GitHub events by weekday and counts repository languages. This is general account activity analysis, not the repository-quality scoring engine.
- **`backend/services/profile_analyser.py`** — Contains an older `ProfileAnalyser` wrapper around profile and event collection. It is not imported by the current `backend/main.py` request flow, so check references before extending it.

### Repository-quality scoring

- **`backend/Quality_Analyzer/repository_quality_analyzer.py`** — Contains `RepositoryQualityAnalyzer`. It asks `RepoAnalyser` for repository-content checks, awards points in documentation, engineering, repository hygiene, and DevOps, then calculates an overall percentage and letter grade.

### Other backend files

- **`backend/models/models.py`** — Defines the Pydantic `User` request model. Currently, it expects a `username` string.
- **`backend/routes/leaderboard.py`** — Defines the `/leaderboard` endpoint, which calls the Adzuna jobs API. This is separate from the core GitHub repository assessment.
- **`backend/requirements.txt`** — Python dependencies.
- **`backend/pyproject.toml`** — Python project/tool configuration.
- **`backend/uv.lock`** — Locked Python dependency versions generated by uv. Usually update it through uv when dependencies change; do not hand-edit it.
- **`backend/.python-version`** — Selects the Python version for tools that respect this file.

## 4. Frontend map

The React application is in **`frontend/Cain/`**.

### App setup and routing

- **`frontend/Cain/src/main.jsx`** — Browser entry point. It mounts React and wraps the app in `GithubProvider`.
- **`frontend/Cain/src/App.jsx`** — Sets up React Router routes for the home page (`/`) and review page (`/Review`).
- **`frontend/Cain/index.html`** — HTML page Vite uses as the frontend entry document.
- **`frontend/Cain/vite.config.js`** — Vite development/build configuration.
- **`frontend/Cain/eslint.config.js`** — ESLint rules for frontend code.

### Pages

- **`frontend/Cain/pages/home.jsx`** — Main dashboard. It reads the username, sends the `POST /` request to the backend, stores returned data in shared state/local storage, and renders the profile, repository-quality score, weekday activity chart, and language information.
- **`frontend/Cain/pages/home.css`** — Styling for the home/dashboard page.
- **`frontend/Cain/pages/review.jsx`** — Review page. It requests `POST /review` from the backend and displays the response as Markdown.
- **`frontend/Cain/pages/Review.css`** — Styling for the review page.

### Shared components and state

- **`frontend/Cain/components/GithubContext.jsx`** — Defines shared React context/state for the username, profile, events, repositories, languages, weekday activity, review text, and quality score. If multiple pages need access to a piece of frontend data, this is where its shared state is currently defined.
- **`frontend/Cain/components/Navbar.jsx`** — Navigation bar component.
- **`frontend/Cain/components/Navbar.css`** — Navigation bar styling.

### Frontend assets and packages

- **`frontend/Cain/src/assets/`** — Images and starter assets used by the frontend.
- **`frontend/Cain/public/`** — Static assets served directly by Vite, including the favicon and icon SVG.
- **`frontend/Cain/package.json`** — Frontend dependencies and commands (`npm run dev`, `npm run build`, `npm run lint`, and `npm run preview`).
- **`frontend/Cain/package-lock.json`** — Locked npm dependency versions. Normally update it through npm, not by hand.
- **`frontend/Cain/.gitignore`** — Frontend-specific ignore rules.

## 5. How the current request flow works

When someone submits a GitHub username on the home page:

1. `frontend/Cain/pages/home.jsx` sends the username to the backend's `POST /` endpoint.
2. `backend/main.py` receives it using the `User` model from `backend/models/models.py`.
3. `backend/services/dataCompile.py` retrieves the GitHub profile, events, and repositories.
4. `backend/Quality_Analyzer/repository_quality_analyzer.py` uses `backend/services/repo_analyser.py` to inspect repository contents and calculate quality scores.
5. `backend/services/analyser.py` calculates weekday activity and language counts.
6. `backend/main.py` returns the results as JSON.
7. `frontend/Cain/pages/home.jsx` saves the results into the shared context and displays them.

In short:

```text
Home page (React)
      |
      | POST / { username }
      v
backend/main.py
      |
      +--> dataCompile.py --------> GitHub API
      |
      +--> repository_quality_analyzer.py
      |           |
      |           v
      |      repo_analyser.py ----> GitHub repository contents
      |
      +--> analyser.py
      |
      v
JSON response
      |
      v
Home page displays results
```

## 6. Important things to know before editing

These are observations about the current branch, not instructions to rewrite everything immediately:

- **The review page and backend do not currently line up.** The frontend calls `POST /review`, but there is no `backend/routes/review.py` in this branch's tracked source tree, and `backend/main.py` does not register a review endpoint. Treat that feature as disconnected until it is deliberately restored or removed.
- **Repository inspection is currently shallow.** `repo_analyser.py` checks the root contents only. It does not yet inspect nested source files, README quality, test quality, or actual code quality.
- **The scoring system currently checks for presence, not quality.** For example, a README receives its documentation points because it exists; its contents are not evaluated yet.
- **The current scoring categories are documentation, engineering, repository hygiene, and DevOps.** If you change category names or the response structure, check the frontend quality display in `frontend/Cain/pages/home.jsx` too.
- **Some old/unused code may remain.** For example, `profile_analyser.py` is not part of the current main request flow. Search for imports/usages before deleting or changing it.
- **The branch contains Python `__pycache__` / `.pyc` files.** These are generated when Python runs code. They are not source files and should not be edited; they should generally be excluded from Git.
- **Environment files are present under `frontend/Cain/`.** Do not put secrets or private API keys in frontend environment variables: frontend variables can be exposed to users in a browser bundle. If any real secret has been committed, remove it from the repository and rotate it.
- **`backend/README.md` currently contains unrelated Windows DNS command output rather than backend documentation.** Do not use it as the project guide; this root-level `NAVIGATION.md` is the code map.

## 7. A sensible place to continue the assessment work

For the repository-quality feature, follow this order:

1. **Collection:** improve `backend/services/dataCompile.py` so Cain can retrieve the repository's full file tree (including nested paths), not just the root directory.
2. **Inspection:** keep repository structure/file discovery in `backend/services/repo_analyser.py` for now, then separate responsibilities into focused analyzers as the feature grows.
3. **Evaluation:** expand `backend/Quality_Analyzer/repository_quality_analyzer.py` so it scores evidence from actual files, not just whether a filename exists.
4. **Response/UI:** update the response from `backend/main.py` and the display in `frontend/Cain/pages/home.jsx` together whenever the assessment output changes.

Make one focused change at a time, and update this guide when files are added, removed, or given a new responsibility.
